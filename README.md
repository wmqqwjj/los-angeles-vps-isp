## 洛杉矶VPS测评该看什么：回程比去程重要得多

去程是你连服务器那一下，回程是服务器把数据送回你家宽带。看视频、开网页、直播推流，卡的都是回程。

回程线路的档次大致是这样分的：电信走 163 骨干（AS4134）属于普通线路，CN2 GIA 是精品；联通走 169（AS4837）是普通骨干，AS9929 是精品；移动走 CMI 是自有出口，CMIN2 是优化档。WePC 这几档套餐的差别，本质就是把联通回程从 4837 换成 9929，价格差 4 澳元。

公开测评显示，WePC 的 9929 系列三网回程都强制走联通 AS9929 回国，去程三家都是直连美国西海岸，再经 Cogent 进洛杉矶机房。这个组合的实际意义是：电信和移动用户虽然去程走自己的骨干，回来也统一从 9929 走，晚高峰不会因为电信 163 拥堵而整段垮掉。

延迟参考区间，洛杉矶到国内电信正常在 150ms 上下、联通 140 到 160ms、移动 160 到 180ms。低于这个区间算运气好，明显高于就得查路由。

真正要盯的是晚上八点到十一点。有些机器白天稳得很，晚高峰丢包 20% 以上，看网页还行，传视频直接废。测一台机器值不值，一条 traceroute 比十张测速截图都有用。

## 标称参数和晚上八点的实际速度，差得有多远

这一节的数据全部来自公开测评，不是本文实测。放进来是因为它决定了你该用什么心态看 AUD$12.90 这种价位。

**Rabisu 洛杉矶，$9.9/年、标称无限流量。** 测评频道的结论原话是「白天可用，晚上你估计是要弃用的」。CPU 单核跑分只有 1000 到 1700，同一商家德国节点单核超过 2000；硬盘读速约为德国那台的十分之一。白天 Netflix 的 fast.com 只跑到 36Mbps，YouTube 在几百 K 到七八千 K 之间波动，1080P 要缓冲。晚高峰 Netflix 不到 200K，YouTube 约 400K，Speedtest 上传下载只剩个位数到 1Mbps。测评者还试过用洛杉矶的三网优化线路去中转这台机器，速度照样上不去，说明出口带宽本身就被超售了。

**RackNerd 洛杉矶 DC03，$21.99/年，标称 1Gbps。** 国内 101 个节点平均延迟约 206ms，电信 184ms、联通 196ms、移动 238ms。国际测速洛杉矶 866Mbps、东京 429Mbps，看着很漂亮。但评论区有用户直接反馈「配置后只有几 Mbps」。标称端口速率从来不是带宽保证。

**QQG.NET 洛杉矶 BGP，$10/年，标称 2Gbps。** 这台反而是三台里表现最像样的：国内平均延迟约 168ms，单线程下载大部分时间能到 90Mbps，晚高峰电信和联通丢包各约 12%，移动大包丢包明显更高。它的移动去程还绕了日本。

三台机器放在一起看，结论很清楚：百元人民币级别的洛杉矶年付机，标称的带宽和流量数字当参考就行，真正决定体验的是那台机器上住了多少人。WePC 的 AUD$12.90 折年约七百多元，不在这个价格带里，但它的 200Mbps 和 1.5TB 同样是共享资源，晚高峰该测还是得测。买之前用官方测试 IP 在自己宽带上 ping 一遍，比看任何测评都准。

## 同一个「联通」，广州和北京的走法不一样

这条几乎没人讲透，但对读者最有用。

Rabisu 那台 $9.9/年的机器，回程路由里藏着一个例外：广州联通从洛杉矶出发，先到香港，再到日本，走 AS10099 转 AS9929 回国，是全篇唯一一条优化路径。而北京、上海、杭州的联通用户，回程走的都是普通 AS4837。同一台服务器，同一个运营商，换个城市，线路档次直接差一级。

RackNerd 那边是反过来的例子：广东移动的回程绕到了德国，延迟超过 270ms。

所以「联通回程 9929」这种描述，你没法默认它对全国联通都成立。正确的做法是拿到测试 IP，在自己的城市、自己的宽带上跑一次 traceroute，看最后一跳落在哪个 AS 号。WePC 官网分类页只写了「9929 高级三网优化」和「4837 三网优化」，没有给出分省路由明细，这一点必须自己验。

## 「双ISP家宽」这个词，不同数据库给的答案不一样

WePC 把「全场双 ISP IP」写进了分类页标题，这是它的核心卖点。但这个标签的含金量，取决于你问的是哪个数据库。

QQG.NET 那台 $10/年的机器是个典型样本：服务器物理位置在洛杉矶，部分数据库判定为英国原生 IP，部分 AI 平台识别成美国，还有平台识别成波兰，住宅 IP 属性无法完全确认，Ping0 判为普通 IDC。同一台机器，四五个数据库给出四种答案。

WePC 这边，公开测评的说法是「原生美国 IPv4，除 ip2location 之外多个数据库显示为家宽属性」。注意这个「除 ip2location 之外」，说明在 IP2Location 的判定里它仍然是机房 IP。ZgoCloud 的双 ISP 系列也有同样的表述：机房托管 IP，不是真家宽，除了 IP2Location 之外主流数据库都识别为双 ISP。

对 TikTok 运营来说，这意味着两件事。一是双 ISP 属性确实比纯机房 IP 友好，风控系统看到的是住宅宽带注册信息；二是它经不起所有平台的一致核验，账号能不能起来还得看内容和其他环境因素，IP 只是其中一环。别把「双 ISP」当成万能钥匙。
